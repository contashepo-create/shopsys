# صلاحيات الخزائن والبنوك

## الهدف

تخصيص خزينة أو أكثر لكل مستخدم مع فصل عرض الرصيد والقبض والصرف والرد والتحويل من/إلى، وخزينة افتراضية وحد مالي مستقل. المنتج Desktop Offline-first؛ تحفظ السياسة لاحقاً في SQLite وتفرض داخل Repository، لا في الواجهة فقط.

## القواعد

- المالك غير مقيد.
- المستخدم القديم بلا `grants` متوافق مؤقتاً حتى أول ضبط.
- بعد الضبط تصبح القائمة Allowlist ملزمة.
- الحد بوحدات العملة الصغرى، و0/null يعني بلا حد.
- التحويل يفحص المصدر والوجهة منفصلين ويضم الرسوم إلى حد المصدر.
- لا تحذف خزينة مخصصة لمستخدم أو لها حركة.
- البيع والشراء والمرتجعات والسندات تفحص الصلاحية قبل إنشاء القيد.
- `view_balance` مستقلة عن صلاحيات تنفيذ الحركة.

## التدقيق والتقارير

تغييرات السياسة تدخل سجل التدقيق باسم المنفذ. تقرير المستخدم يُشتق من اليومية حسب `createdBy` ويعرض القبض والصرف والصافي وعدد العمليات، ويدعم نطاق التاريخ وCSV. القيم في CSV تظل minor units لمنع فقد الدقة، ويُضاف UTF-8 BOM لدعم العربية.

## انتقال SQLite

ينبغي إنشاء جداول user_treasury_grants بقيود FK وUNIQUE(user_id, treasury_code)، وجدول عمليات/JSON مضبوط، معاملة ذرية لتعديل السياسة وسجل التدقيق، وفهرس على journal(created_by, date). لا تنقل سياسة يتيمة أو افتراضياً خارج grants.
