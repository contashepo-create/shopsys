# ماكينات الدفع الإلكتروني

> حالة التنفيذ الدقيقة والمراحل المتبقية: [`متابعة_منظومة_ماكينات_الدفع.md`](./متابعة_منظومة_ماكينات_الدفع.md). هذه الوثيقة تشرح التصميم والتشغيل، ولا يعني ذكر نشاط هنا أن واجهته المباشرة مكتملة؛ ملف المتابعة هو المرجع الحاكم للحالة.

## رحلة التشغيل
1. أنشئ الفروع وحسابات البنك/التسوية.
2. من «الحسابات العامة ← ماكينات الدفع» أضف كل طرفية بكود مستقل واربطها بفرع وحساب.
3. من الصلاحيات امنح المستخدم الماكينات وعمليات التحصيل/الرد/الإلغاء/التسوية/عرض الإجماليات.
4. في POS اختر «بطاقة» ثم الماكينة. يسجل النظام الفاتورة والفرع والمستخدم ومرجع العملية.
5. من بطاقة الماكينة أنشئ دفعة تسوية، وأدخل العمولة وضريبتها وصافي إيداع البنك. العمليات المسواة لا تدخل دفعة أخرى.
6. للمطابقة، اختر الماكينة واستورد CSV محلياً بالأعمدة `providerReference,amountMinor,occurredAt`؛ راجع المطابق والمفقود واختلاف المبلغ والتكرار. الملف لا يُرفع للشبكة.
7. راجع دفعات التسوية وفروقها، ثم صدر تقرير الفترة CSV.

## التغطية عبر الأنشطة
- الكاشير وفاتورة البيع المتطورة ومرتجعاتها: تحصيل/رد مرتبط بالفاتورة.
- المطاعم: قفل أمر الصالة أو التيك أواي أو الدليفري بالماكينة.
- اللوجستيات: تحصيل النقلة كاملاً أو جزئياً بالماكينة.
- المقاولات والمستخلصات وكل مستندات العميل الآجلة: شاشة «تحصيلات العملاء» تطابق الدفعة بالمستخلص أو الفاتورة أو المستند المحدد، أو توزعها FIFO.
- شاشة تحصيلات العملاء الموحدة تستطيع تحصيل المديونيات المرتبطة بعميل عبر الأنشطة، لكنها **لا تعني اكتمال واجهة النشاط المباشرة**.
- مكتمل مباشرة: POS/المرتجع، المطاعم، اللوجستيات، الأقساط، والعيادات.
- إيجار العقارات مكتمل داخل Repository فقط وتبقى واجهته.
- المعامل/التأمين والصيانة والمغاسل والسيارات والمحافظ والعمولات الخارجية ما زالت ضمن قائمة التنفيذ المباشر المفصلة في ملف المتابعة.
- دفع الموردين والمصروفات والعهد وتسويات السائقين ليست تحصيل عميل ولا تُسجل كعملية ماكينة قبض.

## قواعد الأمان
- لا يخزن النظام PAN الكامل أو CVV؛ آخر أربعة أرقام اختيارية فقط.
- الإخفاء في الواجهة ليس حماية؛ Repository يفرض صلاحيات المستخدم والحد المالي.
- الرد والإلغاء يرتبطان بتحصيل أصلي، على الماكينة نفسها، ولا يتجاوزان قيمته.
- لا تحذف ماكينة لها تاريخ؛ غيّر حالتها إلى موقوفة أو متقاعدة.

## نموذج SQLite المستهدف
جداول مستقلة: `payment_terminals`، `payment_terminal_grants`، `payment_terminal_transactions`، `payment_terminal_settlements`، و`payment_terminal_settlement_lines`.
يفرض SQLite قيود `UNIQUE(code)` و`UNIQUE(provider_name, terminal_id)` و`UNIQUE(idempotency_key)` و`UNIQUE(transaction_id)` في سطور التسوية، مع مفاتيح أجنبية للفرع والمستخدم والمستند والحساب.

حفظ عملية التحصيل مع الفاتورة والقيد، وحفظ رد البطاقة مع المرتجع وقيده، وحفظ دفعة التسوية مع قيدها وسطورها، نقاط كتابة ذرية في Repository ويجب تنفيذ كل منها داخل معاملة SQLite واحدة. لا تنفذ idempotency بأسلوب «افحص ثم اكتب» خارج المعاملة. رد البطاقة يستخدم ماكينة وحساب التحصيل الأصليين، والتسوية ذات الصافي غير الموجب تؤجل حتى تضم إلى تحصيلات لاحقة.

## المحاسبة
التحصيل يذهب إلى حساب تحصيلات/تسوية الماكينة. عند كشف البنك تُحوّل القيمة الإجمالية إلى البنك بالقيمة الصافية، ومصروف العمولة، وضريبة العمولة، وحساب فرق التسوية إن وجد. فرق غير صفري يظل ظاهراً ولا يُخفى بالتقريب.
