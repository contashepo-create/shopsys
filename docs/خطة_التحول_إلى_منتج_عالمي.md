# خطة تحول «تَحَكَّم» إلى منتج عالمي

> المرجع التنفيذي المختصر موجود أيضًا في `AGENTS.md`. التقرير التفصيلي للفجوات: `تقرير_التدقيق_الفني_وفجوات_المنافسة_2026-09-21.md`.

## الرؤية

تحويل تَحَكَّم تدريجيًا من تطبيق ERP محلي واسع الوظائف إلى منصة إنتاج موثوقة وآمنة وسريعة، ثم تعميق الأنشطة المختارة حتى تضاهي أفضل التطبيقات المتخصصة من حيث سهولة الاستخدام والاعتمادية وعمق دورة العمل.

## مبادئ التنفيذ

1. لا تطوير أفقي عشوائي؛ المنصة الآمنة أولًا ثم الأنشطة الرأسية.
2. لا ادعاء اكتمال دون اختبار رحلة حقيقية وأجهزة فعلية عند الحاجة.
3. كل تغيير مالي transaction ذرية، idempotent، قابل للتدقيق والاستعادة.
4. تجربة المستخدم جزء من صحة المنتج وليست تجميلًا لاحقًا.
5. التوافق الخلفي والترحيل والنسخ الاحتياطي شروط لأي تغيير بيانات.
6. بعد كل مرحلة تعديل مكتملة: فحص، توثيق، commit، ثم push إلى فرع Arena الحالي.

## المراحل

### المرحلة 0 — تثبيت الجودة والأمن
- حماية قناة الدعم بتوثيق جهاز موقّع وإغلاق CORS المفتوح.
- إدراج مخطط Supabase وسياسات RLS واختبارات عزل المتاجر داخل Git.
- تقوية سر المزامنة وخطة تدوير واسترداد.
- CI إلزامي: TypeScript، lint، Vitest، جميع verify scripts، audit وsecret scanning.
- تصفير تحذيرات lint وإضافة Error Boundary ومعرفات أعطال منقحة من البيانات الحساسة.
- توثيق حدود الامتثال الطبي والقانوني.

### المرحلة 1 — منصة بيانات إنتاجية
- طبقة repository مستقلة عن Zustand وواجهات تخزين قابلة للتبديل.
- SQLite بمعاملات ACID لسطح المكتب، وPostgreSQL/API للوضع السحابي.
- migrations موثقة واختبارات rollback/restore.
- outbox وidempotency keys وقيود مرجعية وسجل تدقيق غير قابل للتعديل.
- مصادقة وتفويض خادميان، جلسات وأجهزة وMFA للمالك.
- مزامنة تفاضلية لكل سجل مع tombstones وحل تعارض واضح.

### المرحلة 2 — تطبيق كاشير/سطح مكتب احترافي
- Electron + installer موقع + تحديثات آمنة وrollback.
- safeStorage/Keychain/DPAPI للمفاتيح.
- تكامل فعلي مع طابعات 58/80mm، قارئ الباركود، الميزان ودرج النقد.
- code splitting وlazy routes وميزانية أداء.
- تشغيل دون إنترنت واستعادة آمنة بعد انقطاع الكهرباء.

### المرحلة 3 — الجودة التشغيلية والامتثال
- Playwright لأهم الرحلات، visual regression، accessibility WCAG 2.2 AA.
- اختبارات تزامن وتحميل واختراق ونسخ/استعادة كارثية مع RPO/RTO.
- monitoring وtracing وstatus/health وrunbooks.
- موصل ZATCA Phase 2 وETA إنتاجيان مع sandbox certification، queue وحالات رفض وإعادة.
- API versioned وwebhooks وتكاملات دفع ورسائل.

### المرحلة 4 — تعميق أول ثلاثة أنشطة
1. سوبر ماركت: replenishment، loyalty، recall، أجهزة وفروع لحظية.
2. مطعم: KDS، modifiers/combos، خريطة طاولات، طلب إلكتروني وتجميعات توصيل.
3. موبايلات وصيانة: intake/diagnostics، صور وتوقيع، موافقة عميل، RMA وportal.

لكل نشاط: مقارنة منافسين، مقابلات مستخدمين، أهم 10 رحلات end-to-end، قياسات أداء واعتماد، وتجربة ميدانية قبل إعلان الجاهزية.

### المرحلة 5 — بقية الأنشطة على دفعات
تعميق الأنشطة بحسب الطلب التجاري، مع عدم فتح أكثر من 2–3 مسارات رأسية بالتوازي. الأولوية التالية تحددها بيانات العملاء لا الانطباع.

## تعريف اكتمال المرحلة

لا تعد المرحلة مكتملة إلا إذا:
- تحققت معايير القبول المكتوبة.
- مرت بوابة الفحص المناسبة دون فشل.
- أضيفت اختبارات تمنع رجوع العطل.
- وُثقت قرارات التصميم والترحيل والتشغيل.
- راجع `git diff` و`git status` للتأكد من عدم تسرب أسرار أو نواتج بناء.
- أُنشئ commit واضح ودُفع إلى فرع Arena الحالي، ثم تم التحقق من نجاح الدفع.
