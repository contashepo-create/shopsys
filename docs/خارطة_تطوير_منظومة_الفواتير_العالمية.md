# خارطة تطوير منظومة الفواتير العالمية

**الحالة:** مرجع تنفيذي ملزم — 2026-09-22  
**المنتج:** تطبيق سطح مكتب محلي Offline-first، SQLite هو مصدر الحقيقة. لا تُبنى المنظومة كـSaaS، ولا يُعد localStorage مخزناً نهائياً.

## 1. الهدف

تطوير خمسة مسارات مترابطة دون تحويلها إلى شاشة ضخمة واحدة:

1. كاشير POS سريع.
2. فاتورة مبيعات B2B متقدمة.
3. مرتجع/إشعار دائن للمبيعات.
4. فاتورة مشتريات متقدمة.
5. مرتجع/إشعار مدين للمشتريات.

تشترك المسارات في محرك مستندات وقواعد محاسبة ومخزون وضريبة وتدقيق واحدة، بينما تعرض كل واجهة ما يلائم نشاطها.

## 2. مبادئ لا يجوز كسرها

- الترحيل عملية ذرية محلية: المستند + المخزون + القيد + الدفعات/السيريالات، تمهيداً لمعاملة SQLite واحدة.
- لا تعديل صامت لمستند مرحّل؛ التصحيح بعكس/إشعار مرتبط مع سجل تدقيق.
- الأموال بوحدات صحيحة minor units، والكميات مقربة وفق سياسة الوحدة.
- كل قيمة تاريخية مؤثرة تُحفظ Snapshot على المستند: السعر، الضريبة، التكلفة، قاعدة التسعير، المخزن، العملة وسعر الصرف.
- المستند يعمل بلا إنترنت؛ الفاتورة الإلكترونية/المزامنة adapters لاحقة لا مصدر حقيقة.
- POS يبقى سريعاً؛ الخيارات B2B المتقدمة لا تُحشر في مسار الكاشير.
- الخصائص الرأسية تظهر عبر capabilities حسب النشاط، لا عبر نسخ محرك الفواتير.

## 4. الدفعات التنفيذية

### INV-0 — الأساس المشترك والمنصة

- [x] تعريف lifecycle موحد: `draft → approved → posted → partially_reversed → reversed/voided` في `core/documentLifecycle.ts`.
- [x] منع إلغاء/إعادة فتح المرحّل وإلزام العكس بمستند مرتبط، مع مفتاح idempotency قابل للتحقق.
- [x] حقول metadata مشتركة: مرجع خارجي، تواريخ مستند/ترحيل/استحقاق، ملاحظات، منشئ/معتمد/مرحل، مع محول قراءة للسجلات القديمة.
- [x] عقد Repository مستقل عن وسيلة التخزين يفرض عملية ذرية ونتيجة duplicate آمنة؛ تنفيذ SQLite الفعلي ما زال لاحقاً.
- [x] نموذج Audit event مرتبط بالمستند الأصلي/العكسي، بلا اعتماد على واجهة أو شبكة.
- [ ] مرفقات المستندات وتخزينها المحلي الآمن.
- [ ] تنفيذ Repository في SQLite مع UNIQUE على idempotency key ومعاملة مستند+قيد+مخزون.
- [ ] دمج الحالات تدريجياً في المستندات الحالية بلا كسر توافق خلفي.

**القبول للدفعة الأولى:** أنواع واختبارات انتقال حالة خالصة، ولا تعتمد على localStorage أو الشبكة أو Supabase. تحقق في `tests/document_lifecycle.test.ts`.

### INV-1 — POS

- حماية سرعة المسح واللمس ولوحة المفاتيح.
- استكمال المخزن/FEFO/السيريال على مستوى السطر.
- تعليق واستكمال، دفع مجزأ، خزينة المستخدم، طباعة وإعادة طباعة مدققة.
- وضع offline recovery ومنع ازدواج الترحيل.

### INV-2 — البيع المتقدم B2B

- عنوان فوترة/شحن، مندوب وعمولة، شروط دفع وأقساط واستحقاق.
- مخزن/مشروع/مركز تكلفة على السطر، تسليم جزئي وحجز.
- خصومات ورسوم وضريبة متعددة، عملة وسعر صرف.
- مؤشر عدالة السعر وSnapshot لقاعدة تسعير العميل × فئة الصنف.
- مسودة واعتماد وترحيل وإشعار تصحيح.

### INV-3 — مرتجع المبيعات

- الموجود: سطر مستقل، سليم/تالف، مستودع استقبال، رد رباعي.
- التالي: حالة «قيد الفحص»، رسوم إعادة تخزين، ربط دفعة/سيريال، رد جزئي متعدد العملات، اعتماد حسب القيمة.
- إشعار دائن قانوني وقالب طباعة/تصدير مستقل.

### INV-4 — الشراء المتقدم

- طلب شراء → أمر شراء → استلام → فاتورة مورد، مع التحويل الجزئي.
- مطابقة ثلاثية وفروق كمية/سعر.
- landed cost: شحن/تأمين/جمارك ومصروفات لاحقة.
- دفعات/سيريالات/صلاحية وحالة فحص عند الاستلام.
- شروط المورد، استحقاقات، عملة، اعتماد حسب القيمة.

### INV-5 — مرتجع الشراء

- إرجاع سطر الأصل لا تجميع الصنف فقط.
- مخزن إخراج لكل سطر وفحص رصيده، دفعة/سيريال محددان.
- سليم/تالف/قيد فحص وسبب لكل سطر.
- استرداد نقدي/تخفيض دين/رصيد لدى المورد/مختلط.
- رسوم شحن وإعادة تخزين وإشعار مدين واعتماد وتدقيق.

### INV-6 — التخصصات والتكامل القانوني

- capabilities للمطاعم، الصيدليات، الملابس، الموبايلات، المقاولات، الخدمات، الجملة والتصنيع.
- محولات فاتورة إلكترونية منفصلة حسب البلد.
- قوالب A4/A5/حراري وPDF/XLSX دون ربط منطق الأعمال بالطباعة.

## 5. ترتيب التنفيذ

1. INV-0 بالتوازي مع مسار Repository/SQLite، لأنه يمنع إعادة بناء الميزات فوق localStorage.
2. إغلاق مخاطر صحة البيانات P0 في المستندات الحالية.
3. INV-5 لرفع مرتجع الشراء إلى مستوى مرتجع البيع.
4. INV-2 ثم INV-4؛ مع إبقاء POS خفيفاً.
5. INV-1 التحصين المكتبي والأجهزة.
6. INV-3 الإضافات، ثم INV-6.

## 6. تعريف الإنجاز لكل دفعة

لا تكتمل الدفعة دون: معايير قبول، اختبارات وحدة وتكامل، توافق خلفي، توثيق، فحص TypeScript/build/lint، مراجعة الفرق، commit وpush ناجحان على فرع Arena الحالي.
