## 0) تقسيم الشاشة — الفكرة الأساسية

الشاشة اليوم عمود واحد طويل يُمرَّر كله، فتختفي أجزاء وتتداخل عند تصغير النافذة. المقترح: **شبكة ستة صفوف بارتفاع الشاشة (`100dvh`) — لا تمرير للصفحة إطلاقاً، والتمرير الوحيد داخل جدول البنود**:

```
┌───────────────────────────────────────────────────────────────────────────┐
│ ① شريط المستند (34px)   رجوع · رقم المستند/الحالة │ مسودات · حفظ · معاينة · [ترحيل وتحصيل F9] │
├───────────────────────────────────────────────────────────────────────────┤
│ ② الترويسة (auto)       العميل · التاريخ · الاستحقاق · المرجع · المخزن · النمط │ بطاقة الطرف │
├───────────────────────────────────────────────────────────────────────────┤
│ ③ شريط الإدخال (30px)   [ماسح الباركود ..........] [كل الأصناف ▾] [تصفية] [إضافة سريعة] │
├───────────────────────────────────────────────────────────────────────────┤
│ ④ البنود (1fr — يأخذ كل الفراغ المتبقي، ورأس الجدول ثابت والتمرير داخله)      │
│    تذييل رفيع: [+صنف] [تكرار] [حذف] [باركود] ⋯ [+مصروف على العميل] [+داخلي] [عمولة] [مرفقات] │
├───────────────────────────────────────────────────────────────────────────┤
│ ⑤ ثلاث لوحات بارتفاع واحد:  [الملاحظات والشروط] [التحصيل الآن] [إجمالي الفاتورة] │
├───────────────────────────────────────────────────────────────────────────┤
│ ⑥ شريط الحالة (26px)    متصل · النشاط/الفرع/المستخدم ⋯ الإجمالي · المتبقي · تخصيص الحقول · PDF │
└───────────────────────────────────────────────────────────────────────────┘
```

**سلوك المقاسات (لا شيء يختفي):**

| العرض | ما يتغير |
|---|---|
| ≥ 1280px | التقسيم أعلاه كما هو: بطاقة الطرف 15rem، ثلاث لوحات في صف. |
| 1080–1280 | بطاقة الطرف تضيق إلى 12rem، وحقول الترويسة تُعيد ترتيب نفسها تلقائياً. |
| 760–1080 | بطاقة الطرف تصير **شريطاً أفقياً** أعلى البنود، واللوحات تصير صفّين (الإجمالي بعرض كامل). |
| < 760px | اللوحات الثلاث تنسدل عمودياً داخل شريط قابل للتمرير بارتفاع محدود، و**الإجمالي والمتبقي يبقيان دائماً في شريط الحالة** فلا يضيعان. أعمدة الكود/الوحدة/الضريبة **تنتقل إلى سطر الوصف داخل الخلية** — لا تُحذف. |

القاعدة: البنود تتمدد وتتقلص، وكل ما عداها ارتفاعه طبيعي وثابت؛ فلا ضغط ولا تداخل ولا اختفاء.

## 1) جدول البنود — ترتيب صارم

| العمود | العرض | المحاذاة والشكل |
|---|---|---|
| م | 2.2rem | وسط، لون باهت |
| كود الصنف | 6rem | LTR أحادي المسافة |
| الصنف / الوصف | مرن | اسم سميك + سطر صغير (المتاح · المخزن) بقص نظيف |
| الكمية | 5.2rem | حقل إدخال LTR |
| الوحدة | 4.6rem | قائمة |
| السعر | 6rem | حقل إدخال LTR |
| خصم % | 4.4rem | حقل إدخال LTR |
| الضريبة | 5rem | رقاقة «معفى» أو النسبة |
| التكلفة · الهامش % | 5.6 + 5rem | **نمط الربحية فقط** |
| الإجمالي | 7rem | **نص محسوب سميك — لا حقل إدخال** (هذا سبب الفوضى الحالية) |
| إجراءات | 4.6rem | ثلاث أيقونات 20px: تفاصيل · تكرار · حذف |

وأيضاً: ارتفاع صف موحّد 2.1rem · رأس ثابت عند التمرير · حدود أفقية فقط · أرقام `tabular-nums` فتصطف تحت بعضها · **إزالة زر «حذف السطر» الأحمر الكبير من ترويسة الجدول** (الحذف موجود في كل سطر، ونسخة مصغّرة في تذييل الجدول).

## 2) اللوحات الثلاث بارتفاع واحد

السبب الحالي: `align-items: start` في الشبكة فيأخذ كل لوح ارتفاع محتواه. الإصلاح: `align-items: stretch` + `height:100%` لكل لوح + `min-height` و`max-height` موحّدان + التمرير داخل جسم اللوح عند الحاجة، فتبقى الثلاثة مستطيلاً واحداً مهما اختلف المحتوى.

## 3) زر الترحيل المكرر

يُحذف زر «ترحيل وتحصيل» من الشريط السفلي نهائياً ويبقى **زر واحد في الشريط العلوي** يحمل المبلغ والاختصار `F9`. الشريط السفلي يتحول إلى **شريط حالة** رفيع: الاتصال · النشاط/الفرع/المستخدم · الإجمالي والمتبقي · تخصيص الحقول · تصدير PDF.

## 4) النوافذ المنبثقة — «عادية» بلا عزل

| اليوم | المقترح |
|---|---|
| `bg-slate-900/55` خلف كل مودال و`bg-slate-950/35` خلف نافذة الأصناف | **لا تعتيم ولا ضبابية إطلاقاً**: الطبقة شفافة و`pointer-events:none`، والنافذة وحدها تستقبل النقر — فترى الفاتورة خلفها وتعمل عليها. |
| ظل ثقيل `shadow-2xl` | إطار بلون العلامة + ظل خفيف جداً فقط ليُميّز النافذة. |
| نافذة الأصناف بلا زر إغلاق، وEscape يعمل على حقل البحث فقط | **زر ✕ ظاهر** في ترويسة النتائج + Escape يعمل على مستوى النافذة + **النقر خارج نافذة الاختيار يغلقها** (نوافذ الإدخال التي فيها بيانات غير محفوظة تبقى على سلوكها الحالي: لا تُغلق بالنقر في الفراغ). |
| — | سطر تلميح ثابت: «Esc للإغلاق · ↑↓ للتنقل · Enter للإضافة». |

## 5) أنماط الفاتورة تصبح فاعلة

اليوم `mode` يؤثر في ثلاثة مواضع فقط، فالأسماء بلا معنى. المقترح أن يكون النمط **حزمة أعمدة وأقسام**:

| النمط | الأعمدة | الأقسام الظاهرة |
|---|---|---|
| **بسيط** | الصنف · الكمية · السعر · الإجمالي | لوحتان فقط (التحصيل + الإجمالي)، بلا شروط ولا مصروفات ولا مرفقات |
| **قياسي** | + الكود · الوحدة · الخصم · الضريبة | اللوحات الثلاث + مصروف على العميل |
| **ربحية** | قياسي + **التكلفة · الهامش %** | + سطر «الربح المتوقع» في لوحة الإجمالي |
| **متقدم** | قياسي | + المصروفات الداخلية والعمولات ومراكز التكلفة والمشروع والمرفقات والعملة الأجنبية |

مع سطر تحت مبدّل النمط: «النمط يغيّر الأعمدة والأقسام الظاهرة فقط — لا يمس الحساب ولا القيد»، والنمط يُحفظ في تفضيلات المستخدم. وبوابة تحقق تمنع رجوع الأسماء الميتة (تثبت أن كل نمط يغيّر مجموعة الأعمدة فعلاً).

## 6) زر المصروفات

تُحذف بطاقة «المصروفات» الكبيرة، وتتحول إلى **رقاقتين صغيرتين في تذييل جدول البنود**: «+ مصروف على العميل» و«+ مصروف داخلي» بعدّاد لكل منهما، ومعهما «+ عمولة موظف» و«📎 مرفقات» — كلها تفتح نفس النوافذ الحالية بلا أي تغيير محاسبي.

## 7) ما لا يتغير (تعهد)

المحرك المحاسبي والقيود والذمم والضريبة والعملة الثانية والمرفقات وصلاحيات الخزائن — **لا يمسها هذا العمل إطلاقاً**؛ التغيير كله في الشكل والتقسيم وسلوك النوافذ. وبعد التنفيذ تعاد كل البوابات (201) واختبارات الوحدة (386) خضراء قبل الدفع.

## ما أحتاجه منك قبل التنفيذ

1. هل التقسيم الستّي أعلاه معتمد؟
2. نمط الفاتورة الافتراضي عند فتح فاتورة جديدة: **قياسي** أم **متقدم**؟
3. في الشاشات الضيقة: أفضّل إبقاء اللوحات الثلاث منسدلة بتمرير داخلي مع تثبيت الإجمالي في شريط الحالة — أم تفضّل أن تصير اللوحات الثلاث **تبويبات** (شروط / تحصيل / إجمالي) يظهر منها واحد؟
