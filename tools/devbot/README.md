# مركز تحكم المطوّر — shopsys-control (بوت تليجرام + Cloudflare)

بوت خاص بالمطوّر يدير اشتراكات العملاء: إصدار مفاتيح التفعيل الموقّعة، التجديد،
الحرق/الإبطال، البحث، الرسائل — ونقاط REST التي تقرؤها نسخة العميل
(`GET /about` · `GET /revoked` · `GET /subscription/:deviceId` · `GET /notifications/:deviceId`) متوافقة مع
`app/src/core/cloud.ts`. توافق التوقيع مضمون بالاختبار الذهبي
`app/tests/devbot_license_compat.test.ts` (يولّد مفتاحاً بالخوارزمية نفسها ويتحقق به
عبر `verifyLicenseKey`).

> **أنت (المالك) من ينشر هذا على حسابك في Cloudflare** — كل الأوامر هنا تنفَّذ من هذا
> المجلد `tools/devbot/`. تستخدمه نسخة التطبيق الجديدة للتراخيص وصفحة «حول» عبر العنوان
> `https://shopsys-control.mobileshop2026.workers.dev`. تحديثات برنامج ويندوز ينشرها GitHub، لا هذا العامل.

## لوحة الأزرار
بعد النشر أرسل `/بدء` للبوت لفتح لوحة عربية بالأزرار. إذا لم يوجد عملاء، اختر «إضافة أول عميل»؛ أدخل اسمه مرة واحدة ثم معرّف الجهاز الذي يظهر في شاشة التفعيل، وسيصدر له مفتاح بالإعدادات العامة. بعد ذلك تختار العميل باسمه، وتستطيع تخصيص إعداداته أو إرسال تنبيه له. التنبيه العام أو الخاص يظهر في جرس التطبيق، ويظهر كتذكير منبثق أثناء تشغيله.

التخصيص الخاص محفوظ باسم العميل ولا تستبدله تغييرات الإعداد العام. التغييرات تطبق على الرخص الجديدة؛ ولتطبيقها على جهاز لديه مفتاح سابق، أصدر مفتاحاً جديداً من صفحة العميل وأدخله في التطبيق.

## أول نشر — بالترتيب حرفياً

### ① أنشئ بوت تليجرام (مرة واحدة)
1. افتح [@BotFather](https://t.me/BotFather) → `/newbot` → اختر اسماً (مثل «تحكم — المطوّر») ومعرّفاً.
2. احفظ **التوكن** (شكل `123456:AA...`).
3. اجلب **معرّفك الرقمي**: أرسل رسالة لأي بوت مثل @userinfobot — يرد برقم (مثل `123456789`).

### ② ولّد زوج مفاتيح التوقيع (مرة واحدة)
```bash
node scripts/keygen.mjs
```
- سطر `PUBLIC` → استبدل به الثابت `DEVELOPER_PUBLIC_KEY_B64U` في
  `app/src/core/license.ts` **قبل** إصدار النسخة التي ستحمل أول مفاتيح — ثم لا تغيّره أبداً.
- سطر `PRIVATE` → سر يُحفظ خارج git (احتفظ بنسخة آمنة!):
  ```bash
  cd tools/devbot
  npx wrangler secret put DEV_PRIVATE_KEY_B64U   # الصق المفتاح الخاص
  ```

### ③ أنشئ مساحة KV واضبط الإعدادات
```bash
npx wrangler kv namespace create SHOPSYS_CONTROL
```
معرّف مساحة KV المستخدمة حاليًا محفوظ في `wrangler.toml`. إذا أنشأت مساحة جديدة، استبدل المعرف بالقيمة الجديدة.

### ④ باقي الأسرار ثم النشر
```bash
npx wrangler secret put TELEGRAM_BOT_TOKEN     # توكن البوت
npx wrangler secret put TELEGRAM_ADMIN_ID      # معرّفك الرقمي
npx wrangler secret put WEBHOOK_SECRET         # سلسلة عشوائية طويلة (openssl rand -hex 24)
npx wrangler deploy
```

### ⑤ اربط الـwebhook
```bash
curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=https://shopsys-control.mobileshop2026.workers.dev/telegram/<WEBHOOK_SECRET>&secret_token=<WEBHOOK_SECRET>"
```

### ⑥ جرّب
أرسل للبوت: `/بدء` ثم:
```
/اصدر SHOP-TEST-TEST-TEST basic «محل تجربة» 365
```
جرّب المفتاح في التطبيق (شاشة التفعيل تعرض معرّف الجهاز `SHOP-…` — انسخه من عند العميل).
ثم `/حرق <المفتاح>` وتأكد أن العميل يرفضه بعد مزامنة قائمة الإبطال أو إعادة تشغيل التطبيق.

## الأوامر (محصورة بمعرّفك — أي حساب آخر يُتجاهل)

| الأمر | الوظيفة |
|---|---|
| `/اصدر <جهاز> <خطة> <اسم> [أيام] [نشاط] [+مستخدمون] [+فروع] [+ميزات]` | إصدار/تجديد مفتاح. الخطة: `trial`/`basic`/`pro`/`lifetime`. الأيام افتراضياً 365، و`0` أو lifetime = مدى الحياة. النشاط يقصّر المفتاح عليه (قرار 28) |
| `/حرق <مفتاح أو بصمة>` | إبطال نهائي — يدخل قائمة `revoked` التي يجلبها العميل |
| `/بحث <مفتاح أو بصمة>` | بيانات المفتاح وحالته (سليم/محروق) |
| `/رسالة <جهاز> <نص>` | يكتب `dev:<جهاز>.message` — ⚠️ لا يُعرض داخل التطبيق (استخدم التنبيهات بدلها) |
| `/حول <نص>` | النص التعريفي في «حول» (`/حول مسح` يعيده للافتراضي) — **لا يمسّ** بيانات التواصل |
| `/اشتراكات` | كل الأجهزة المسجلة |
| `/تذكير [أيام]` | 🔔 المنتهية والموشكة على الانتهاء (الافتراضي 10 أيام — قابل للضبط 1–90) |
| `/احصائيات` | عدد الأجهزة والمنتهية والموشكة والمحروقة والتنبيهات |
| `/تسجيلات` | 🆕 العملاء الجدد الذين أكملوا معالج أول التشغيل (يصلك كل واحد تلقائياً) |
| `/تنبيهات` | 📬 التنبيهات المرسلة وعدد إقرارات القراءة («قرأه 12 جهاز») |
| `/دعم` | 💬 محادثات الدعم — المنتظرة ردّك أولاً · `/دعم <جهاز>` محادثة جهاز |
| `/رد <جهاز> <نص>` | رد يصل العميل داخل التطبيق خلال 30 ثانية (أو Reply على بلاغ الدعم نفسه) |

### لوحة الأزرار (بعد `/بدء`)
| الزر | الوظيفة |
|---|---|
| 🆕 التسجيلات | كل بلاغات العملاء الجدد بأسمائهم وهواتفهم وبريدهم |
| 👥 العملاء · ➕ إضافة عميل | سجل التراخيص وإصدار المفاتيح |
| ⏳ الاشتراكات | المنتهية/الموشكة + «⏳ تغيير النافذة» (1–90 يوماً، تُحفظ وتُسري على الـcron) |
| 📊 إحصائيات | نفس أرقام `/احصائيات` |
| 🔔 تنبيه للجميع | **اختر الدرجة أولاً**: 📣 إعلان · ⚠️ مهم (نافذة منبثقة) · 🚨 عاجل (إقرار إلزامي) |
| 📬 التنبيهات المرسلة | ما أُرسل وعدد من أقرّ بالقراءة |
| 💬 الدعم | صندوق محادثات الدعم بالأزرار: قراءة ← «✍️ الرد على العميل» |
| 📝 صفحة «حول» والتواصل | كل حقول التواصل حقلاً حقلاً + حقول حرة + قنوات إضافية + معاينة |

### التذكير اليومي التلقائي (cron)
`wrangler.toml` يضبط `crons = ["0 7 * * *"]` (07:00 UTC = 10:00 صباحاً بتوقيت القاهرة).
القواعد: لا منتهية ولا موشكة ⇒ **لا رسالة إطلاقاً**، وعلامة `digest-sent:<اليوم>` تمنع
التكرار لو أُطلق الجدول أكثر من مرة. النافذة المستخدمة هي نفسها التي تضبطها من اللوحة.

**التجديد** = `/اصدر` مرة أخرى بنفس معرّف الجهاز بتاريخ انتهاء جديد (يُرسل للعميل مفتاحاً
جديداً يستبدل به القديم). حرق المفتاح القديم اختياري.

## تحديث النسخة المنشورة
بعد أي تعديل على `src/worker.js`:
```bash
npx wrangler deploy
```

## الأسرار الإضافية (تحديث 2026-10-08)

```bash
# جسر قناة الدعم (بند 1) — المحادثات مخزّنة في عامل cloud/worker.js واللوحة هنا،
# وبوت تليجرام واحد له ويبهوك واحد ⇒ بدونه لا يصل ردّك (Reply) للعميل أبداً.
npx wrangler secret put SUPPORT_BRIDGE_URL      # رابط عامل الدعم كاملاً (من مجلد cloud/)
npx wrangler secret put SUPPORT_BRIDGE_SECRET   # 32 محرفاً عشوائياً فأكثر
# وفي مجلد cloud/ ضع القيمة نفسها حرفياً:
#   npx wrangler secret put SUPPORT_BRIDGE_SECRET
```
بلا هذين السرّين تبقى `/دعم` و`/رد` وزر «💬 الدعم» معطّلة برسالة إرشادية عربية —
ولا يتعطل أي شيء آخر في اللوحة.

## ملاحظات أمنية
- كل الأسرار عبر `wrangler secret put` — لا تُكتب في ملفات داخل المجلد (`.gitignore` يحجبها احتياطاً).
- رابط الـwebhook يحوي `WEBHOOK_SECRET` — من يعرفه يستطيع إرسال تحديثات؛ اجعله طويلاً وعشوائياً.
- نقاط العملاء للقراءة فقط (صفحة «حول»، بصمات الإبطال، حالة الاشتراك، والتنبيهات) ولا تُرجع مفاتيح التفعيل.
- `POST /register` (بلاغ عميل جديد) و`POST /notifications/:id/ack` (إقرار قراءة) نقطتا **كتابة** عامتان
  بحكم أن تطبيق العميل لا يستطيع حمل سرّ (حزمة المُصيّر قابلة للقراءة). التحصين: قبول فقط
  لمعرّف جهاز بصيغة `SHOP-XXXX-XXXX-XXXX`، تعقيم كامل للحقول، حد حجم 8 كبايت (يُفحص
  طول النص الخام لا ترويسة `content-length` وحدها)، وبلاغ واحد لكل جهاز ⇒ الأسوأ إزعاج لا اختراق.
- روابط «حول» تُعقَّم بالرفض لا بالتنظيف: `http/https/mailto/tel` فقط، وأي مسافة أو اقتباس
  أو زاوية ⇒ رفض كامل (المحتوى يُعرض في `href` عند كل العملاء).
- جسر الدعم (`/support-bridge` في عامل cloud/) مصادَق عليه بسرّ مشترك بمقارنة بزمن ثابت،
  ومغلق كلياً لو كان السرّ غير مضبوط أو أقصر من 16 محرفاً.
- لو انكشف المفتاح الخاص: ولّد زوجاً جديداً + حدّث `license.ts` + أصدر نسخة جديدة، واحرق
  كل المفاتيح القديمة (`/اشتراكات` ثم `/حرق` لكل واحدة).
