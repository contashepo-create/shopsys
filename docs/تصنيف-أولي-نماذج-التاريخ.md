# تصنيف يدوي أولي لواجهات التاريخ

هذه جولة تصنيف استرشادية، **ليست حصراً لجميع نماذج البرنامج**. فهرس `فهرس-أولي-لنماذج-التاريخ.md` الآلي يحصي أغلفة معينة فقط ويخلط عرضاً وتعديلاً وإعداداً مع المعاملات؛ لم تُصنَّف كل صفوفه بعد. القائمة التالية راجعت العنوان ومسار الحفظ والأثر الظاهر في المصدر، ولا تعني أن هذه العمليات صالحة للإدخال بأثر رجعي دون تصميم واختبارات للتسلسل والفترات والتزامن.

| النموذج / مسار الحفظ | التصنيف والقرار | الحالة |
|---|---|---|
| فاتورة بيع `postSale` وفاتورة شراء `postPurchase` والشراء السريع | تاريخ إصدار مالي؛ المستقبل ممنوع والسنة المقفلة مرفوضة، ويختلف عن الاستحقاق والصلاحية | نُفذ سابقاً |
| أمر تغيير مشروع `addChangeOrder` | تاريخ مستند غير مرحّل؛ وقت الإنشاء والاعتماد مستقلان، والمستقبل لا يؤجل أثر الاعتماد | نُفذ سابقاً |
| قياس حصر المشروع `saveProjectSurvey` | تاريخ قياس غير مالي، ليس تاريخ كل الكميات السابقة | نُفذ سابقاً |
| دفعة العميل `receiveClientAdvance` | تاريخ تحصيل وقيد مع ترتيب استرداد الدفعات؛ الماكينة يوم التسجيل | نُفذ سابقاً |
| إصدار مستخلص `addProjectExtract` | تاريخ فاتورة وقيد وضريبة وتسلسل كميات ومقدمات؛ لا يجوز خلطه بوقت التسجيل | نُفذ سابقاً مع حارس تعديل المستخلص المؤرخ سابقاً |
| تحصيل محتجز `releaseRetention` | تاريخ تحصيل وقيد، والإقفال يحصل وقت التسجيل؛ حماية رصيد الأصل والفرع وتسلسل المستخلصات والماكينة | نُفذ في هذه الجولة |
| صرف داخلي `postConsumption` | حركة مخزون وقيد تكلفة؛ تاريخ الحركة يجب أن يُصمم مع تاريخ التكلفة والرصيد والموافقة | مطلوب؛ لا يكفي حقل واجهة |
| إتلاف مخزون `postWastage` | حركة مخزون وقيد تكلفة؛ يلزم فحص تواريخ الدُفعات والصلاحية والتكلفة والموافقات | مطلوب؛ لم يُنفذ |
| تحويل مخزني `postTransfer` | حركة مخزون غير مالية؛ يحتاج تاريخ حركة مستقل مع منع إحداث ترتيب مخزون تاريخي غير صحيح | مطلوب؛ لم يُنفذ |
| إذن مواد المشروع `issueMaterials` | حركة مخزون وتكلفة مشروع؛ مراجعة تسلسل الصرف وتكلفة المخزون وتوقيت المستخلصات والموافقة | مطلوب؛ لم يُنفذ |
| عملية المحافظ `postWalletService` | تمويل وتحصيل وضريبة وهامش ودين؛ يوجد وسيط تاريخ في المخزن لكن الواجهة لا تمرره. يلزم حراسة التواريخ والماكينة والذمة والخزائن والقفل قبل إظهاره | مطلوب؛ لم يُنفذ |
| صرف سلفة الموظف `grantEmployeeAdvance` | تحصيل/صرف وذمة موظف؛ تاريخ وقيد وتأثير الاسترداد والمسير والخزينة | مطلوب؛ لم يُنفذ |
| سداد سلفة نقدي `repayEmployeeAdvance` | تحصيل وتخصيص لاسترداد السلفة؛ يلزم منع تقديم السداد على أصله أو قلب ترتيب التخصيص والمسير | مطلوب؛ لم يُنفذ |
| خصم/جزاء الموظف `addEmployeeDeduction` | استحقاق يؤثر في المسير؛ يلزم تحديد الفرق بين تاريخ الجزاء والتسجيل وتوقيت الاستقطاع | مطلوب؛ لم يُنفذ |
| استحقاق عمولة الموظف `addStaffCommission` | قيد استحقاق مرتبط بالمصدر والتسوية؛ يجب فحص تاريخ المصدر والصرف والعكس | مطلوب؛ لم يُنفذ |
| تعديل/إلغاء عمولة | إجراء عاكس تدقيقي، لا يُفترض أن يكون تاريخ المستند الأصلي قابلاً لإعادة الكتابة | يحتاج تصميم مسار تصحيح، لم يُنفذ |
| طلب اعتماد ومسار الموافقات | حدث توقيع/صلاحية يُختم وقتياً، لا يسمح تقويم حر بتزوير وقت الموافقة؛ قد يُطلب تاريخ المستند الأصلي في نموذجه منفصلاً | لا يُضاف تاريخ معاملة لمجرد غياب الحقل |
| تصدير/استيراد مفتاح الاسترداد، ومرفقات المستند، وقوالب الطباعة، ومسودات الفاتورة | أدوات أمن/ملفات/إعداد أو اختيار، وليست بذاتها معاملة مالية جديدة | لا تاريخ ترحيل مستقل هنا؛ راجع تاريخ المستند الأصلي عند إصداره |
| اختيار الفاتورة الأصلية للمرتجع | خطوة اختيار وليست إصدار المرتجع نفسه | لا تاريخ على نافذة الاختيار؛ نموذج المرتجع وحراسه يحتاجان مراجعة منفصلة |
| استيراد الموظفين / تحرير بيانات موظف | بيانات مرجعية؛ تاريخ الالتحاق موجود في محرر الموظف، وليس تاريخ قيد | لا يستلزم تاريخ معاملة لكل تغيير بيانات |

كل نموذج لم يرد هنا أو ورد بعنوان ديناميكي في الفهرس **غير مصنّف بعد**. النماذج التي حُددت أعلاه «مطلوبة» لا تُعتبر منجزة. يلزم أيضاً تدقيق الصفحات والمعالجات خارج أغلفة الفهرسة، وحالة منطق الفروع والاعتماد والسنوات لكل مسار قبل إتاحة الماضي؛ وجود تاريخ في النوع أو في حقل غير مستخدم لا يثبت صحة الترحيل.
