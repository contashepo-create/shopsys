# قاعدة البيانات التجريبية — وضع التطوير فقط

ملف SQLite حقيقي يعيش مع كود المشروع: **`app/demo-db/demo.sqlite`**.
يحتوي بيانات جاهزة لأربعة أنشطة مختلفة، ولكل نشاط بياناته المستقلة:
أصناف متعددة الخواص · عملاء · موردون · **مخازن متعددة** · **فروع متعددة** ·
**خزائن وبنوك ومحافظ إلكترونية تابعة لبنوكها** · **ماكينات دفع** ·
**فواتير بيع وشراء**.

> لا تدخل هذه البيانات نسخة الإنتاج إطلاقاً: واجهة القراءة/الكتابة إضافةُ Vite
> تعمل في `serve` فقط، وكل كود الواجهة محروس بـ`import.meta.env.DEV`.

## كيف تجرّب نشاطاً

1. `npm run dev`
2. اضغط زر **«بيانات تجريبية»** أسفل يسار الشاشة.
3. اختر النشاط ⇐ **«جرّب هذا النشاط»**. الانتقال إلى نشاط آخر يمسح بيانات السابق
   تلقائياً ثم يحمّل الجديد (لا اختلاط بين الأنشطة).

## كيف تعدّل البيانات

| الطريقة | الخطوات |
| --- | --- |
| من داخل التطبيق | عدّل الأصناف/العملاء… ثم **«حفظ التعديلات في القاعدة»** — تُكتب في `demo.sqlite` فوراً |
| بأي أداة SQLite | افتح `app/demo-db/demo.sqlite` بـ`sqlite3` أو DB Browser وعدّل الجداول مباشرة |
| من ملف البذور | عدّل `seed.data.mjs` ثم `npm run demo:build` (يعيد بناء القاعدة من الصفر) |
| تراجع | زر **«إعادة الضبط»** في اللوحة = إعادة بناء من `seed.data.mjs` |

```bash
npm run demo:build                 # إعادة بناء القاعدة من ملف البذور
sqlite3 app/demo-db/demo.sqlite    # تصفّح/تعديل مباشر
```

## البنية

- `schema.sql` — الجداول الثلاثون (كلها تحمل عمود `activity`) — تشمل منذ المرحلة ⑥:
  الموظفين والحضور والإجازات ومسيرات الرواتب وعروض الأسعار وأوامر الشراء
  ومستندات الهالك ومعدات التأجير وعقوده ومصروفاته وعقود مقاولي الباطن
  والمستخلصات، مع `expiry_date` في بنود الشراء لدفعات الصلاحية، ومنذ §96:
  `contracting_docs` (مستندات كل أقسام المقاولات: مشروع يدوي · BOQ · موازنة ·
  أوامر تغيير · خطابات ضمان · عمال يومية · أذون صرف · تكاليف · دفعات مقدمة ·
  سندات موسومة بمشروع · تحصيلات · شراء مربوط · مهام · موافقات) وعمود
  `convert` في العروض (العرض الفائز يتحول مشروعاً عند التحميل).
- `seed.data.mjs` — البيانات المقروءة القابلة للتعديل (مصدر البناء).
- `build.mjs` — يبني `demo.sqlite` من المخطط + البذور.
- `vitePlugin.mjs` — واجهة `/__demo/*` لوضع التطوير (قراءة · كتابة · إعادة بناء).
- المبالغ كلها **أعداد صحيحة بالقروش** (`*_minor`) التزاماً بقاعدة المشروع.

التحميل داخل التطبيق يمر بالإجراءات الرسمية (`postSale` / `postPurchase` /
`setOpeningBalance` / `setAttendanceDay` / `accruePayrollSlips` + `postVoucher`
بسداد القسائم / `addQuotation` / `addPurchaseOrder` / `postWastage` /
`convertQuotationToProject` / `addSubContract` + `addSubAdvance` +
`addSubCertificate` / `addProjectExtract` / `addEquipment` /
`openRental` + `closeRental` / `addEquipmentCost`)،
فتُبنى القيود المحاسبية والمخزون والذمم بصدق بدل حقن حالة صامتة.

سيناريوهات جاهزة لكل نشاط (المرحلة ⑥): حضور وإجازات ومسير رواتب مسدَّد بسند
صرف (الجروسري)، دفعة منتهية الصلاحية تظهر في لوحة الفرز + مستند هالك جزئي،
دفعة قاربت الانتهاء (الصيدلية)، أمر شراء خضار مفتوح (المطعم)، وعرض سعر زي
مدرسي بضريبة 14٪ وأمر استيراد (الملابس). وفي الأنشطة الثلاثة الجديدة:
**مقاولات** — عرض يتحول مشروعاً ثم عقد مقاول باطن (محتجز 5٪، استقطاع 1٪،
مقدمة 3.2م، شهادة 16م) ومستخلص أول بنسبة إنجاز 35٪ · **تأجير معدات** —
أسطول من 5 معدات بعدادات ساعات وخطة صيانة، وثلاثة عقود (مختلط التحصيل،
آجل، نقدي مقفل بخصم تالفيات 50 ألف) ومصروفات وقود وصيانة وإصلاح ومشغل ·
**أعلاف** — أصناف بيع بالوزن والميزان ووحدات (طن) وأمر توريد صوامع.
