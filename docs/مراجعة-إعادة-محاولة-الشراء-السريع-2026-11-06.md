# الشراء السريع وإعادة محاولة تأكيد الحفظ — 2026-11-06

أثبت اختبار واجهة يستخدم محرك الشراء الحقيقي وقفل/تخزين محاكيين أن الإدخال السريع كان ينشئ فاتورتين عند إعادة المحاولة بعد فشل تأكيد الحفظ، لأن الاستدعاء لم يحمل مفتاحاً ثابتاً. أصبح لكل فتح جديد للمحرر مفتاح مستقل، ويظل ثابتاً أثناء إعادة المحاولة. إذا عادت محاولة بالقيم نفسها وكان المستند محفوظاً يعيده المحرك بلا تكرار القيد أو المخزون. وإن غيّر المستخدم القيم بعد نجاح الترحيل وتعذر تأكيده، يرفض المحرر إعادة الإرسال المعدّلة بدلاً من إظهار نجاح بيانات لم تُرحّل، ويطلب إعادة القيم أو مراجعة الفاتورة المسجلة. تُعرض رسالة توضح أن الترحيل حدث لكن تأكيد الحفظ فشل.

حدود: المفتاح في ذاكرة نافذة الإدخال السريع فقط وليس مسودة محفوظة؛ لا يمكن ضمان منع التكرار بعد إغلاقها أو تعطل التطبيق أو فقد الكتابة، فتجب مراجعة سجل الفواتير قبل إدخال جديد. القفل والتخزين محاكيان في اختبار الواجهة، ولا يثبت الاختبار تعطل SQLite أو تعدد نوافذ فعلية. كما يُفحص مسار طلب الاعتماد المتكرر منفصلاً.
