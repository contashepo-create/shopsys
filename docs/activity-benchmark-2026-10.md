**المنهجية:** جرد فعلي لكل ما في التطبيق من وحدات (17) وخصائص أصناف (6) وقدرات
عرضية (ولاء، فروع، LAN، بوت تليجرام، فاتورة إلكترونية، شيكات، أصول، عهد،
موافقات، مراكز تكلفة، سندات، ورديات، جرد، باركود، تعدد طابعات حرارية، نسخ

بحلّه العالمي المتخصص، وتصنيف الفجوات:

- 🔶 **فجوة جزئية** — الأساس موجود وناقصه عمق المتخصص (مذكور بدقة).
- 🔴 **فجوة معلنة** — غير موجودة وتحتاج جولة/جولات (خطة أولوية أدناه).
- ⛔ **خارج النطاق الحالي** — قرار هندسي/تجاري مؤجل (مبرره مذكور).

## تفصيل الأنشطة الأهم (الأسس المقارنة)

**سوبر ماركت vs Square/LS Retail:** POS أصناف متعددة الوحدات + باركود/ميزان
+ صلاحية FEFO وتنبيه + جرد ومخازن وتحويلات + ورديات وإقفال نقدي + قوائم
أسعار (جملة/قطاعي/VIP) + ولاء نقاط (نمط Square) + أقساط + فروع. المنافس
يتفوق في: رفوف ومناضد وطلبات توصيل أونلاين.

**مطعم vs Toast/Foodics:** شبكة طاولات وأوامر مفتوحة (صالة/تيك أواي/دليفري)
مع بون مطبخ وإقفال بفاتورة واحدة + وصفات تخصم خاماتها عند البيع + أوامر إنتاج
(صوصات/عجائن) + وزن وصلاحية. المنافس يتفوق في: QR منيو وبوابة طلبات
أونلاين — تحتاج سحابة دائمة (مرحلة Cloudflare).

**صيدلية vs PioneerRx:** صلاحية إلزامية بصرف FEFO وتنبيهات + وحدات
(شريط/علبة) + باركود + ولاء نقاط وأقساط وموردين. المنافس يتفوق في: التفاعل
الدوائي والوصفة الإلكترونية وفوترة التأمين — الثلاثة مسؤولية طبية/تعاقدية
لا ندّعيها في نظام محاسبي (موثق بصراحة).

**مقاولات vs Procore:** مشروعات ببنود ومستخلصات ومحتجزات + محاسبة مقاولات
كاملة (تكاليف مباشرة/مقاولي باطن/ربحية) + مشتريات ومخزون + عهد. المنافس
يتفوق في: Gantt ووثائق موقع والمخططات — سنسد الجدولة.

**موبايلات vs RepairShopr:** تذاكر صيانة بحالات وانتقالات وتأخير + سيريال/IMEI
وضمان + قطع تُصرف من المخزون بربحية تذكرة + خدمات المحافظ (نمط mobileshop
الربح = المحصَّل − المدفوع للمزوّد) + أقساط. المنافس يتفوق في: إشعار العميل
بالحالة (سنسده عبر بوت التليجرام الموجود).

**عيادة vs Kareo:** ملفات مرضى بتاريخ مرضي منظم + زيارات وكشوفات + خطط علاج
ومواعيد + نتائج مرفقات. المنافس يتفوق في: فوترة تأمين معقدة — نطاقنا محاسبي.

**إيجار معدات vs Rentman:** أسطول معدات + عقود إيجار بمدد وتأمينات مستردة +
فواتير + تقارير ربحية. المنافس يتفوق في: تكرار دوري تلقائي وتقويم إتاحة
مرئي.

**عقارات vs Buildium/سند:** عقارات ووحدات + عقود إيجار بأقساط وتأمينات +
سعي إدارة أملاك الغير + بيع العقارات المملوكة بأرباح/خسائر. قوي محلياً.

## سد فجوات هذه الجولة (منفذ)

1. **قسم إضافي لأي نشاط** (طلب المالك — اكتُشف أن قناة العقد الموقّع كانت
   مكسورة عند آخر حلقة): التطبيق كان يدعم `extraModules` الموقّعة منذ عقد
   2026-09-28 (بوابة المرحلة 4 خضراء) لكن **أمر البوت `/اصدر` لا يمرر
   `وحدات=` أصلاً** فلا سبيل عملياً للمنح. سُدّت القناة: `/اصدر ... وحدات=
   maintenance,laundry` يتحقق من الوحدات الـ17 ويرفض المجهولة ويوقّعها
   ويسجلها في سجل الجهاز. وواجهة الإعدادات صارت تعرض الوحدات الـ17 كلها:
   الممنوحة (افتراضيات النشاط ∪ ممنوحات المفتاح) بإيقاف/إعادة إظهار ذاتية —
   والإيقاف يخفي الشاشات فقط وبياناتها تبقى — وما لم يُمنح بشارة «بكود
   الدعم» (لا فتح ذاتياً — التزاماً بالعقد: الترخيص يحمي قيمة الوحدات).
2. **إثبات سلامة البيانات عبر التحديثات:** اختبار `migration_safety_v110`
   يمرر قاعدة قديمة النسخة (v22) عبر مسار الإقلاع الحقيقي (persist + migrate)
   ويثبت بقاء كل عنصر بمعرفه واستكمال الحقول الجديدة افتراضياً — بلا فقد.

## ضمانات «لا فقد بيانات» (سؤال المالك — الأدلة بالكود)

- **إضافة ميزات (تحديث تطبيق):** كل ترحيل SQLite داخل معاملة واحدة مع
  **نسخة احتياطية إلزامية قبل تنفيذه** (`pre-migration-N`) وفحص سلامة بعده؛
  الترحيلات مرقمة مسجلة فلا تُعاد. طبقة المتجر: `migrate` تستكمل كل حقل
  جديد بقيمة افتراضية (`?? []`/`?? null`) وتحتفظ بكل قديم — مثبت باختبار
  المسار الحقيقي أعلاه.
- **إلغاء ميزة/قسم:** لا يوجد حذف فيزيائي إطلاقاً — «حذف» الصف = وسم
  `deleted_at` (soft delete)، وإيقاف قسم يخفي شاشاته فقط وبياناته باقية.
- **التراجع لإصدار أقدم من التطبيق:** اللقطة تُقرأ بالحقول المعروفة فقط —
  الحقول الأحدث تُهمل بأمان (توافق رجعي سلس).
- **نسخة القاعدة قبل أي مخاطرة:** نسخ مزدوجة تلقائية يومية + قبل كل ترحيل +
  قبل الاستعادة + درع التلف عند الإقلاع (v1.0.9).
