# تطابق إعادة إرسال مسودة الفاتورة — 2026-11-06

أثبتت اختبارات المحرك أن مفتاح المسودة وحده كان يعيد فاتورة البيع أو الشراء السابقة حتى لو تغيّرت الكمية، بما في ذلك بعد اعتماد المسودة؛ قد تعرض الواجهة نجاحاً دون ترحيل المدخل الجديد.

يحفظ المحرك الآن مع الفواتير الجديدة ذات مفتاح المسودة تمثيلاً مرتباً لمدخل الترحيل المطبّع، ويقارنه بالمدخل المعاد. يعيد الفاتورة بلا قيد أو حركة مكررة فقط عند التطابق؛ يرفض المحتوى المختلف أو فاتورة عُدلت لاحقاً. يستبقي طلب الاعتماد دليل المدخل الأصلي قبل إضافة تاريخ التقديم أو تعديلات نطاق الفرع، لضمان مقارنة المدخل الأصلي عند إعادة المحاولة. الفواتير القديمة أو طلبات الاعتماد القديمة التي لا تحفظ دليلاً كافياً تُرفض إعادة محاولتها للمراجعة، دون تعديل تاريخها أو افتراض تطابق محتواها.

قبل الإصلاح فشلت أربعة اختبارات لعدم رفض المحتوى المختلف والبيانات التاريخية؛ بعد الإصلاح نجحت الاختبارات، بما في ذلك اعتماد بيع مع تثبيت التاريخ وإعادة المحاولة بعد تعديل الفاتورة. الاختبارات الموجهة 38 حالة في 6 ملفات ثم حالتان إضافيتان لذات المحرك؛ `typecheck` و`lint:strict` ناجحان وأعيد توليد مصفوفة المحرك.

الدليل هو نص JSON منظم من بيانات الإدخال، وليس بصمة تشفير؛ يُخزّن ضمن بيانات الفاتورة وقد يكرر بيانات السطور والملاحظات، ما يزيد حجم التخزين. يجب تطبيق حماية بيانات الفواتير والنسخ الاحتياطية عليه أيضاً. لا يضمن التطابق سلامة التخزين أو تزامن النوافذ، ولا يرمم سجلات قديمة أو يثبت ملكية طلب اعتماد تاريخي لعملية سابقة.
