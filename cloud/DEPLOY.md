# المرحلة ⑥ — السحابية على Cloudflare (جاهزة، النشر بقرار المالك)

> **القاعدة الثابتة:** كل الكود هنا جاهز، لكن **لا يُنشر شيء إلا بقرار صريح
> من المالك** — كما اتُّفق في خطة المراحل. المجلد يحمل مكوّنين مستقلين.

## ١) Worker قناة الدعم والترخيص (قائم — من جولة سابقة)

`worker.js` + `wrangler.toml`: لوحة تحكم المطوّر السحابية — صفحة «حول»،
حرق المفاتيح، حالة الاشتراكات، وقناة الدعم الفني عبر بوت التليجرام
(نصوص فقط، اعتماد جهاز HMAC، حد معدل، CORS صريحة — التفاصيل الكاملة
في ترويسة `worker.js` وتعليقات `wrangler.toml`).

النشر: `cd cloud && npx wrangler deploy` ثم ضبط الأسرار
(DEV_BOT_TOKEN · DEV_CHAT_ID · TG_WEBHOOK_SECRET · SUPPORT_ALLOWED_ORIGINS ·
SHOPSYS_PRIVATE_KEY · **SUPPORT_BRIDGE_SECRET**)
وتسجيل الويبهوك كما موثق في `wrangler.toml`.

### جسر لوحة المطوّر `POST /support-bridge` (بند 1 من تدقيق 2026-10-08)

نقطة مصادَقة تتيح لمركز التحكم في `tools/devbot` قراءة محادثات الدعم
المخزّنة هنا (`chat:<deviceId>`) والرد عليها من اللوحة أو من البوت، بأربعة
إجراءات: `inbox` (قائمة المحادثات) · `thread` (رسائل محادثة) · `reply`
(ردّ من اللوحة) · `telegram-reply` (ردّ وصل من تليجرام).

- **السرّ واحد في العاملين:** `wrangler secret put SUPPORT_BRIDGE_SECRET`
  هنا وفي `tools/devbot` — **القيمة نفسها حرفياً**، ASCII فقط (العربية في
  ترويسة HTTP ترمي استثناءً)، 32 محرفاً عشوائياً فأكثر.
- وفي `tools/devbot` اضبط أيضاً `SUPPORT_BRIDGE_URL` = عنوان هذا العامل
  (مثل `https://shopsys-control.<account>.workers.dev`).
- بلا السرّ (أو بأقل من 16 محرفاً) تكون النقطة **مغلقة كلياً** ولا تنكسر
  أي وظيفة أخرى — قناة الدعم المباشرة في التطبيق تعمل كالمعتاد.

### تنبيه: `GET /about` موجود في العاملين — والمعمول به مركز التحكم

التطبيق يقرأ صفحة «حول» من **مركز التحكم** (`tools/devbot` ← `LICENSE_CLOUD_BASE_URL`)،
وهناك تكتب اللوحة المستند المنظّم (هاتف/واتساب/تليجرام/بريد/موقع/عنوان/مواعيد +
حقول حرة + قنوات). نقطة `/about` في هذا العامل شكل قديم (بلا تلك الحقول) ولا
يقرأها التطبيق ولا يكتبها شيء هنا — **لا تملأ مفتاح `about` في هذه المساحة وتتوقع
ظهوره للعملاء**. أُبقيت للتوافق مع مستهلكين قدامى محتملين.

### تنبيه: ملخّص الاشتراكات موجود في العاملين

هذا العامل يحمل `subscriptionDigest()` خاصة به تعمل على مفاتيح `sub:*`
(تُكتب عند إصدار الترخيص) وتستجيب لأمر «تذكير» ولـ cron **معطّل** في
`wrangler.toml`. الملخّص المعتمد في تدقيق 2026-10-08 (بنود 3 و4) هو
الموجود في `tools/devbot` — cron يومي `0 7 * * *` على مفاتيح `lic:*` مع
إزالة تكرار بمفتاح `digest-sent:<يوم>`. **لا تفعّل الـ cron هنا** حتى لا
يصل المطوّر ملخّصان مختلفان في اليوم نفسه.

## ٢) نسخة الويب على Cloudflare Pages (جديد هذه الجولة — كود جاهز فقط)

نسخة **الواجهة بالمتصفح** كاملة (الأصناف، الفواتير، القيود، الكاشير،
التقارير…) برابط عام بلا تثبيت. ملف الإعداد: `pages-wrangler.toml`
(مستقل تماماً عن Worker — لا يمسه).

### الصدق التقني — اقرأه قبل النشر

| | نسخة الويب (Pages) | نسخة سطح المكتب (EXE) |
|---|---|---|
| بيانات المتجر | تخزين **المتصفح على جهاز المستخدم** — لا تُرفع لأي سيرفر | قاعدة SQLite **مشفرة** AES-256-GCM |
| مسح بيانات المتصفح | يمسح البيانات (النسخ الاحتياطي مسؤولية المستخدم) | القاعدة ملف مستقل لا يمسحها شيء |
| الطباعة الصامتة وتعدد الطابعات | لا — حوار الطباعة الاعتيادي فقط | ✓ |
| إرسال المستندات PDF عبر واتساب | لا (رسالة صادقة داخل التطبيق) | ✓ |
| التحديث التلقائي | بتحديث النشر نفسه (فوري للجميع) | ✓ electron-updater |
| بوت التليجرام للنسخ | ✓ | ✓ |

**المزامنة بين الأجهزة عبر السحابة ليست في هذه المرحلة** — كل متجر
بياناته محلية عند مستخدمه، ولا تُستهلك أي خدمة سحابية للصفحات بالتصميم
(لا Functions ولا KV ولا D1).

### خطوات نشر الصفحات (بيد المالك)

**الطريقة الأولى — أوامر مباشرة (أسرع):**

```bash
npm install -g wrangler
wrangler login          # يفتح صفحة Cloudflare للموافقة

cd app && npm install && npm run build
cd .. && npx wrangler pages deploy app/dist --project-name tahakom-web
```

أول نشر يسأل عن إنشاء المشروع — أجب بنعم؛ ستحصل على رابط
`tahakom-web-xxxx.pages.dev` (يمكن ربط دومين خاص لاحقاً من اللوحة).

**الطريقة الثانية — ربط المستودع (تحديث تلقائي بكل دفعة):**

1. لوحة Cloudflare ← Workers & Pages ← Create ← Pages ← Connect to Git.
2. اختر مستودع `contashepo-create/shopsys`.
3. إعدادات البناء: **Root directory:** `app` · **Build command:**
   `npm run build` · **Output:** `dist`.
4. كل دفعة للفرع الرئيسي تنشر تلقائياً.

### قبل النشر — قائمة تحقق

- [ ] إصدار `app/package.json` هو المراد نشره.
- [ ] `npm run verify:all` أخضر محلياً من جذر `app/`.
- [ ] تجربة محلية: `cd app && npm run build && npm run preview` — افتح
      الرابط وتأكد أن التطبيق يعمل كاملاً بالمتصفح.
- [ ] قرار المالك الصريح بالنشر (هذه الوثيقة لا تنشر شيئاً بنفسها).

### كلفة التشغيل

Cloudflare Pages: مجاني حتى 500 دفعة/شهر للفريق بعرض نطاق غير محدود
للزوار — ملفات ثابتة (HTML/JS/CSS) لا تستهلك حوسبة سحابية، فلا فاتورة
مفاجئة.
