# دليل الترحيل: مستودع خاص + رف إصدارات عام للتحديث التلقائي

> **الهدف:** مصدر المشروع (`shopsys`) يصبح خاصاً، ويستمر التحديث التلقائي
> للعملاء عبر مستودع عام منفصل يحمل الإصدارات الجاهزة فقط — **بلا أي كود
> مصدري وبلا أي توكن يُشحن للعملاء**.

## المعمارية (كما نُفذت في v1.0.16)

```
shopsys (خاص لاحقاً)               tahakom-releases (عام — رف فقط)
├─ كل الكود والاختبارات والCI       ├─ releases/ فقط: exe + latest.yml + blockmap
├─ سير desktop-release:            └─ لا فروع كود ولا مصدر إطلاقاً
│   1) يبني المثبت (بلا توكن)
│   2) يتحقق أن app-update.yml داخل المثبت يشير للرف العام
│   3) ينشر للرف العام (سر RELEASES_REPO_TOKEN — توكن محصور)
│   4) يمرآء الإصدار هنا مؤقتاً (للعملاء القدامى — خطوة تُزال)
└─ أجهزة العملاء تفتح الرف العام بلا توكن → latest.yml → تنزيل وتحديث
```

**لماذا لا يتضرر أي عميل؟** ملف `app-update.yml` داخل المثبت هو الذي يحدد
وجهة طلب التحديث — وهو من إعداد `publish` في `electron-builder.yml` الذي
يشير الآن إلى `tahakom-releases`، بغض النظر عن مكان البناء.

## خطوات المالك (بمحاذاة الأرقام)

### 1) إنشاء رف الإصدارات العام (مرة واحدة — دقيقة)

1. GitHub ← زر + أعلى يمين ← **New repository**.
2. الاسم: **`tahakom-releases`** — مالك: `contashepo-create` — **Public**.
3. علّم **Add a README file** (حتى يكون له فرع افتراضي للإصدارات).
4. أنشئه. (اختياري: اكتب في الوصف: «رف إصدارات تطبيق تَحَكَّم — التحديث
   التلقائي. المصدر في مستودع خاص».)

### 2) توكن النشر المحصور (مرة واحدة — دقيقتان)

1. GitHub ← صورة حسابك أعلى يمين ← **Settings** ← أسفل يسار:
   **Developer settings** ← **Personal access tokens** ← **Fine-grained tokens**
   ← **Generate new token**.
2. الاسم: `tahakom-releases-publisher`.
3. **Repository access**: «Only select repositories» ← اختر
   **`tahakom-releases` فقط** (لا تختار shopsys!).
4. **Permissions** ← Repository permissions ← **Contents: Read and write**.
   (كل ما عداه: No access).
5. أنشئه وانسخ التوكن (يظهر مرة واحدة).
6. في مستودع `shopsys`: **Settings ← Secrets and variables ← Actions ←
   New repository secret** — الاسم: **`RELEASES_REPO_TOKEN`** — القيمة:
   التوكن.

> **نطاق هذا التوكن:** كتابة محتويات رف الإصدارات العام فقط. لا يستطيع
> قراءة أو لمس مستودع المصدر حتى لو تسرب. أما العملاء فلا يستلمونه أبداً —
> يبقى سراً داخل GitHub Actions.

### 3) إصدار الترحيل v1.0.16 (بيدي بعد خطوتيك أعلاه)

عند دفع وسم `v1.0.16` يبني السير وينشر للرف العام + مرآة هنا.
**العملاء القدامى (1.0.12/1.0.15)** يجدون المرآة فيثبّتون 1.0.16 فينتقلون
تلقائياً لرف الإصدارات من التحديث التالي.

### 4) التحقق قبل الخصخصة (بيدك — دقيقة)

من جهاز عليه 1.0.12: افتح التطبيق ← دعه يفحص التحديث ← سيثبّت 1.0.16 ←
بعد التثبيت افحص التحديث مجدداً: يجب أن يستجيب (سيقرأ من الرف العام —
ستجد الإصدارات في `github.com/contashepo-create/tahakom-releases/releases`).

### 5) الخصخصة (بيدك — متى شئت بعد خطوة 4)

`shopsys` ← **Settings** ← أسفل الصفحة **Danger Zone** ←
**Change repository visibility** ← **Make private**.

ما يتأثر وما لا يتأثر:

| البند | بعد الخصخصة |
|---|---|
| تحديث العملاء (على ≥1.0.16) | ✅ يعمل — يقرأ من الرف العام |
| CI والفحوص والبناء | ✅ تعمل (Actions له صلاحية مستوده الخاص) |
| نشر الإصدارات الجديدة للرف | ✅ يعمل (توكنه محصور بالرف) |
| مرآة shopsys للقدامى | ⛔ تتوقف فائدتها (هذا متوقع — انظر خطوة 6) |
| من فاته 1.0.16 قبل الخصخصة | يثبّت أياً من إصدارات الرف العام يدوياً مرة واحدة |

### 6) إزالة خطوة المرآة (اختياري — تنظيف بعد الترحيل)

بعد أن تطمئن أن عملاءك على ≥1.0.16، احذف من
`.github/workflows/desktop-release.yml` الخطوة المسماة
«مرآة إصدار الترحيل في هذا المستودع…» (وتعليقها). لا شيء آخر يتغير.

## أسئلة متوقعة

**س: هل يستطيع أحد قراءة مصدري من الرف العام؟**
ج: لا — الرف يحوي ملفات المثبت الجاهزة فقط، وهي كانت تُنزَّل أصلاً من
المستودع العام الحالي. مستوى الانكشاف أقل من الوضع الحالي.

**س: لو انتهت صلاحية توكن النشر؟**
ج: لا يمس العملاء إطلاقاً (لا يعرفونه) — يتوقف فقط نشر الإصدارات
الجديدة حتى تولّد توكن جديداً وتحدث السر. أنشئه بمدة أطول أو جددها
قبل الانتهاء.

**س: هل أستطيع الرجوع عن كل هذا؟**
ج: نعم وقبل الخصخصة بلا أي أثر: أعِد `publish.repo: shopsys` في
electron-builder.yml وأزل الخطوات الجديدة. بعد الخصخصة الرجوع يتطلب
إعادة فتح المستودع عاماً.
